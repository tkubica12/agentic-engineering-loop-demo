Using this page

Each card below is one scene of the hour, in order, with its minute window. In slides mode a click anywhere advances, arrow keys step, O opens the scene index, and F goes full screen. Escape leaves presentation and returns you to this article view, where the same cards read as a list; the Slides button in the top-right resumes presenting from where you were.

The page is a single file plus a local assets folder. It has no network dependency and works from a memory stick.

Warning

Every state shown on this page is reproduced from a prepared artefact. None of it is happening now. Say that once when you switch to this page, then present normally.

Scenes 1 to 4

One change is followed from a telemetry signal to a governed release and back. Nine lifecycle stages carry it, shown here in eleven demo scenes. Only one lifecycle stage is coding, and the ninth returns to the first.

The seven questions that decide whether an agent's diff survives contact with a real system are platform questions: was intent written down, is the proposal reviewable, does deterministic evidence exist, does policy allow it, who is accountable, how does it reach production, and what does production say afterwards.

Live equivalent: the showcase article, chapter one.

A staged incident ships a Container Apps revision with a payment-gateway configuration regression. Checkout returns HTTP 500. Azure SRE Agent correlates telemetry with connected GitHub source, a rollback subagent shifts all traffic to the known-good revision under an identity scoped to that one app, the Activity Log attributes the write to the agent, and recovery is verified rather than assumed.

Warning

It does not prove GitHub write-back. The subagent's instructions tell it to raise an issue for source fixes, but its configured tool list has no GitHub connector. That is a designed next step.

Source: tkubica12/azure-sre-agent, MIT. Prepared artefact: fixtures/prepared/08-sre-incident.json.

Work management and engineering evidence are different systems of record. Jira keeps planning and reporting; the evidence an agent works from moves closer to the code. Each repository later gets one disposition: Migrate, Mirror, or Leave in place. Those are per-repository decisions, not calendar phases.

  • Phase 1, week 1: observation only, contract in one repository.
  • Phase 2, week 2: make existing checks required.
  • Add CODEOWNERS and a ruleset so approval means something.
  • Add one read-only agent with safe outputs.
  • Then pick a lane, when the decision is reversible.
